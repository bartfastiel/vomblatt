# Decisions

Only decisions made by people that someone might question later belong here – product, rules, limits, trade-offs.
Purely technical solutions (how something is built) belong in the code and its tests.

One file per decision, date as prefix, half a page: Context, Decision, then Why or Consequences – and Rejected,
because the path not taken is the part that gets forgotten and re-proposed a year later. A superseded decision keeps
its file and names its successor in the status.
